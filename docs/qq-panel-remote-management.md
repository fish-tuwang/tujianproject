所有写操作仅接受 POST JSON、同源 Origin、X-Panel。后端逐路径白名单转发到固定本机地址；不转发图鉴 Cookie、Authorization 或上游 Set-Cookie。未开放任意 URL、命令或代理接口。修改账号、设备、OneBot、面板口令及宿主文件路径的配置仍禁止从远程覆盖。

“QQ登录与连接诊断”可在公司获取新的QQ二维码，保留现有账号容器及登录目录。刷新会等待图片内容实际更新，已在线、正在扫码确认/初始化或需要手机安全验证时不会强行打断。最终扫码确认仍由本人完成。

启动、停止、强制重启均只切换 Mac 聊天进程，QQ账号容器保持。停止聊天后自动更新遇到代码发布可能恢复服务，不能把停止聊天当成永久停用QQ账号。

## 隔离功能验收

新增 `scripts/qq_panel_sandbox.py`。在 Mac 使用已安装的 FatFish 虚拟环境运行：

```sh
"$HOME/Library/Application Support/LittleAtlasQQ/fatfish/venv/bin/python" scripts/qq_panel_sandbox.py
```

脚本只复制公开 Python/HTML 源码，在临时目录生成虚拟配置、图片、歌曲和记忆；禁止网络连接和启动进程，QQ 网关为内存模拟，绝不启动另一个账号或向真实群发消息。调用真实面板读取/保存处理器与真实 `_admin_send` → Mac 适配器链路，涵盖群/私聊文字、纯表情、图文、媒体路径、歌曲上传/编辑/删除，以及设置/人设/表情/心情管理。临时目录结束即删除，报告只含检查名和结果。

这类沙箱检查不等于音乐平台实际扫码成功、语音服务合成成功或真实 QQ 已收图；外部服务依赖与平台登录需另行核验。公开版没有 `personcard.py`，人物卡目前标记 unsupported，已有的记忆、关系和情绪管理独立可用。恶作剧关闭属于原配置状态，验收不会擅自开启。

2026-11-23 修复：`Path.as_uri()` 会编码 Mac 的 `Application Support` 空格及中文文件名；适配器现在只对 file URI 解码一次，把图片/语音转为 base64 后交给 QQ 容器，原始路径中的 `%` 不重复解码。素材缺失在宿主侧明确失败，不再让容器报 ENOENT。文件上传同样正确处理 file URI。

手机端表情选择优化：`fatfish_extensions/panel_ui.py` 在输出面板时适配公开版 HTML。代发选择/取消/切换表情与发送后清除选择只更新选中样式，保留已有图片节点；表情管理开关只更新当前卡片和计数，重复点击同一保存中的开关会忽略，避免整片图片闪灰与重新下载。搜索和筛选仍正常重建结果列表。此适配随本仓库 qqbot 更新生效，不直接修改上游发布文件。

后续发送排障：修复 URI 后，实际 QQ 日志仍出现 `rich media transfer failed`，属于媒体上传阶段失败，不能与 ENOENT 混称已修复。现增加 WebP 发送副本兼容转换（静态→PNG，动画→GIF；保留原素材），以及 `FatFish/delivery-state.json` 私有诊断，只记录时间、动作、成功状态、分类及返回码，不保存正文/接收人/媒体/密钥。代发页显示完整的短失败说明，不再被上游80字截断吞掉原因。格式兼容调整属于排查修正，是否解决腾讯端上传仍以用户真实收图为准；沙箱不冒充真实QQ成功。

## 连接保护与故障记录

2026-11-23 增补：每30秒守护检查同时核对 QQ 的已登录、初始化和实际离线标志；不会仅凭已登录认定在线。保存最多40次状态变化、最近确认在线时间与最近一次离线持续时间。保存的登录记录查询失败不会把在线账号误判为掉线。确认安全验证时不重登；扫码确认/初始化/恢复连接期间不打断。

快速登录仍只使用原账号的有效保存记录，连续离线至少60秒才考虑恢复，最多每小时3次；短暂在线不会清空滚动小时限额。没有记录时明确要求手机扫码，不能凭脚本生成登录凭证。探测失败不触发登录/重启，媒体上传失败独立记录，不能作为重登依据。历史故障只保留状态分类和时间，不保存腾讯原始登录错误、验证链接或聊天。

远程“QQ登录与连接诊断”展示保护状态、新鲜度、快速登录是否可用、最近在线/离线时长、最近发送分类和状态变化。图鉴会话失效会要求重新登录控制面板，不再被显示成机器人停止或QQ掉线。

守护器变更属于宿主部署：测试通过后备份私有 `guard.py`，将仓库 `scripts/mac_qq_guard.py` 原子替换到原路径，保留现有 LaunchAgent 和30秒周期，先单次检查实际状态。无需重新运行安装流程或重新设置登录账号，不重启账号容器。若需回滚，只恢复备份的脚本；新增状态字段兼容旧守护器。此保护提高诊断与恢复可靠性，不保证腾讯登录态永不失效。

假在线补充修复：实际出现 `get_status.online=true`、WebUI已登录且ready，但持续 `1006514 网络连接异常`、无真实收发的情况。现在连续至少3次发送网络失败、跨越至少60秒且最近失败在5分钟内时，面板与守护器显示“收发不可用”，不会再以缓存在线标志覆盖故障。成功发送会清除连续失败证据。仅有有效快速登录记录且本小时未重启过时，守护器允许一次恢复客户端；没有快登记录时不循环重启，需人工恢复并可能扫码。恢复后旧发送失败计数失效，避免同一证据反复触发。扫码/初始化和明确安全验证不被干预。
