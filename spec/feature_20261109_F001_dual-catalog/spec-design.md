# Feature: 20261109_F001 - 双图鉴微信小程序

## 需求背景

建立展示 Tomica 多美卡玩具车与宝可梦的微信小程序，方便按分类查找、查看单项详情，并由后台定期采集来源更新。本设计基于用户确认的新建需求、全国宝可梦图鉴范围，以及对简版方案的继续推进指示。

## 目标

2026-11-09 执行补充：用户要求一次完成开发、测试和部署，并直接查看页面效果后调整。增加使用同一只读 API 的响应式浏览器演示预览，展示双图鉴列表、筛选和详情；小程序正式发布仍等待 AppID 与 HTTPS 域名。部署时保留可查看的演示服务，不清理用户要求保留的交付服务，仅清理临时测试进程。

- 多美卡支持按玩具发售年份、汽车品牌及二者组合查找，支持名称、编号搜索和详情展示。
- 宝可梦覆盖全国图鉴，按全国编号数值升序排列，支持名称、编号搜索、属性筛选和详情展示。
- 数据由后台定时同步到本地数据库，用户浏览不触发来源网站抓取。
- 首版聚焦浏览、搜索、详情与数据维护；不包含交易、社区、收藏和拥有清单。

## 方案设计

### 页面与交互

底部提供“多美卡”和“宝可梦”两个图鉴入口，各自使用搜索框、筛选区和图片卡片列表。列表分页加载，详情返回后保留查询条件与浏览位置。加载中、无结果、图片缺失和接口失败均提供明确状态。

多美卡列表展示主图、名称、汽车品牌、编号、基础车型发售年份。筛选支持品牌、年份及组合条件，年份明确标为“基础车型发售年份”，并提供“未知”。详情展示原文名称、可用的中文展示名、系列、编号、比例、基础车型发售年月、版本列表、版本独立发售日期（若有）、来源和更新时间。原站 WANTED 等收藏状态不能自动视为有实物照片。

宝可梦列表展示编号、图片、中文名和属性。详情展示中日英名称、属性、身高体重、特性、进化关系与不同形态；字段不存在时显示“暂无资料”。不同形态归属同一全国编号，在详情内切换，列表默认每个全国编号仅显示一次。进化关系保留分支及条件，点击已收录对象可以跳转。

### 架构与方案选择

采用微信原生小程序 + 用户现有服务器后端 + PostgreSQL 18 + 图片存储接口。后端提供只读图鉴接口；独立采集任务负责来源访问、解析、校验和发布；受认证保护的轻量管理页面负责同步状态、重试和人工纠错。用户在实施计划阶段提供现有服务器并授权数据库准备及部署，生产复用已运行的 PostgreSQL 实例，不影响既有插件或其他应用。

生产目录为 `/opt/dual-catalog`，已准备独立数据库 `dual_catalog` 和应用角色；定时任务与浏览接口分开运行，避免采集影响查询。服务器保存连接秘密，本地不复制。小程序客户端通过微信开发者工具构建与发布，服务器承载数据库、接口、管理页面与采集任务。真实 AppID、HTTPS 域名及图片交付配置在发布验收中核对；服务器准备现状见同目录 `deployment-state.md`。

链路：来源网站 → 来源适配器 → 待发布数据 → 校验与差异检查 → 正式数据库 → 查询接口 → 小程序。

两个来源各有独立适配器；统一保存来源、同步状态、图片状态和任务日志，但不把汽车版本与宝可梦形态强行合成同一种业务对象。

### 多美卡数据规则

- 基础车型记录：内部 ID、系列、原站车型标识、编号、代次、原文名称、展示名称、汽车品牌、基础车型发售年月、比例、主图、来源定位。
- 版本记录：内部 ID、关联车型、原站版本标识、版本说明、配色或套装信息、版本独立发售日期、产地、图片、来源定位。
- 编号不是唯一键：同一编号可以跨年代用于不同车型；同一车型也可能有多个版本。原站存在不完整编号和重复分类，不能仅按编号或名称合并。
- 优先使用来源车型锚点与可靠版本标识定位；缺少稳定标识时使用来源位置、原始字段和图片路径建立映射，歧义交由人工处理，不按易变列表顺序生成永久身份。
- 品牌统一为汽车制造商品牌，使用别名表处理日文、英文和中文名称。特注方、销售商、套装品牌另列，不能直接映射成汽车品牌。无法确定时保留未知。
- 基础车型年份与版本年份分开存储。样本的“1970.9～”可以表示基础车型发售时间，不能直接赋给该车型所有后续版本；底盘或生产批次编码也不直接当成发售日期。
- 首次导入优先使用编号分类作为基础车型入口，再对关联特注、套装等页面补充版本。来源是个人收藏目录，不承诺覆盖官方全部产品。

### 宝可梦数据规则

- 基础记录以全国编号作为唯一业务标识，数据库保存整数，展示格式如 #0001，排序使用整数。
- 使用 52poke 全国图鉴列表发现条目，再读取对应的主详情页；原用户提供的 Pokémon GO 列表不作为全国图鉴完整性的依据。
- 形态记录以“全国编号 + 规范化形态标识”区分，保留形态属性、图片和差异字段。
- 进化关系单独记录来源、目标和条件。百科游戏、动画、旁支系列等内容按章节区分，不从无关章节误取数据。
- 动态总数以同步时来源列表为准，不写死；缺失详情计入待补充清单。

### 定期采集与发布

建议每天北京时间 03:00 检查入口、识别新增与变更，每周日 04:00 完整核对已发现页面。此处是产品运行设计，尚未创建任何真实定时任务。

首次导入完整目标清单，分批处理详情；后续优先使用来源提供的修改标识或 HTTP 缓存头判断变化，不具备条件时比较页面内容摘要。任务支持持久化进度、断点续跑和互斥锁；每来源默认串行、请求间隔至少 2 秒，并遵循来源实际允许的更严格限制。429、网络超时和服务器错误采用有限次数退避重试，失败留待下一轮；不绕过访问控制。

解析结果先进入待发布区域，检查必填字段、编号冲突、来源定位、异常空数据、数量异常及图片关联。通过校验后才发布相应批次；来源间允许独立成功或失败。解析模板失效或大批量缺失时停止该批发布并记录异常。

单页失败保留旧数据，入口暂时消失不自动删除正式记录；删除需人工确认。成功读取但内容未变化时仅更新检查时间，不改变内容更新时间。人工纠正字段保留覆盖记录，后续抓取不静默覆盖。

小程序详情展示数据更新时间和来源；管理页面展示上次成功时间、失败页面、待补充条目与新增/修改数量，支持手动触发同步和重试。手动任务与定时任务复用互斥机制。

### 图片与内容来源

采集前检查站点访问规则和内容、图片的复用条件，保存署名与来源信息。图片处理与文本同步分离，失败时显示占位图，不导致整条记录丢失。获得可用授权的图片可转存对象存储并通过自有 HTTPS 地址提供；发布前确认图片交付方式，不假定可以直接复制全部图片或长期使用来源外链。

### 查询与管理边界

查询接口支持多美卡品牌、基础车型年份、关键词与分页；宝可梦支持全国编号、名称、属性与分页。详情通过稳定内部 ID 或全国编号读取。分页采用稳定排序，避免相邻页重项。管理功能必须认证，普通客户端不能触发采集、修改数据或读取后台凭证。

## 实现要点

- 多美卡 HTTP 首页、菜单、编号样本页和本田特注样本页已返回 200。首页使用 frameset，需独立读取 menu.html 和内容页。采用兼容 Shift_JIS 的 CP932 解码，路径中的空格等字符正确编码。
- HTTPS 测试出现域名不匹配的证书错误；当前验证使用原 HTTP 地址，不关闭 HTTPS 证书校验。小程序只访问自有后端；正式部署时还需验证部署网络能访问来源。
- 菜单抓到 1085 个链接，此数是导航链接数，不是车型数量或唯一页面总数。编号页含嵌套表格、车型与版本混排，正式解析需要保留上下文，不能用全文正则直接生产数据。
- 宝可梦全国列表与妙蛙种子详情已通过网页访问工具读取；尚需验证部署端对 52poke 的直接请求、解析与图片访问情况，网页工具可读不代表后台采集已打通。
- 首个实施阶段以少量代表样本验证：旧车型、新车型、多版本、缺失字段、特注、不同宝可梦形态和分支进化。样本通过后再全量导入。
- 仓库当前无已有应用实现和 spec/global 文档，本设计不依赖现有模块。服务器专用数据库及受限账号已创建并完成连接校验；业务表迁移、采集服务及小程序尚未实现。
