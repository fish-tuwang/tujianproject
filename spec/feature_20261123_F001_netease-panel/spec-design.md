# 网易云扫码关联接口修复

## 问题与授权

用户希望从异地 `/qq-panel/#sing` 关联网易云。页面已有扫码按钮，上游 FatFish
已有 `music_login`，但本仓库代理对全部 POST 返回只读403，登录流程无法抵达 Mac。
2026-11-23用户明确确认仅为网易云关联开放最小例外，其他操作保持只读。

## 方案

复用上游的二维码生成、扫码轮询、登录检查，不修改或复制上游运行目录。
只允许所有者在同源 HTTPS 页面提交 JSON，路径固定为 `api/music/login`，
只接受 `platform=netease` 与 `action=start/poll/check`，不接收多余字段和查询串。
保留 X-Panel 校验，外部 TLS 终止于 Nginx，校验外部 HTTPS Origin 而非隧道内部协议。
只转发固定 Host/X-Panel 和经过校验的两字段，不转发图鉴会话或客户端鉴权头。
响应仅返回二维码、展示状态和检查结果，过滤平台 key、Cookie及Set-Cookie，禁止缓存。
网络失败、重定向、超限或格式异常只返回通用失败，不回显私密上游详情。

页面注明网易云例外与本机存储；关闭其他平台扫码、注销和音乐管理按钮，
服务端仍拒绝这些操作。取消二维码展示仅为浏览器本地动作。
只改图鉴API代理与文档/测试，由现有图鉴自动更新发布，不改 QQ 账号、群范围、
凭据、数据、人设、宿主更新器或官方 harness 插件。

## 验证与边界

测试覆盖授权、同源、TLS反代、JSON类型/字段/大小、操作白名单、响应过滤、
无凭据转发、上游失败、原有只读和URL改写场景；同时运行规定的QQ更新与守护回归。
不在公司启动QQ账号。发布报告区分推送、Mac拉取与网易云实际扫码确认；
模拟接口不能证明用户已登录，会员/地区和平台服务约束照常适用。
